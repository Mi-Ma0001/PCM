Vue d’ensemble

Ce guide vous emmène du fichier plan-maintenance-cms.zip jusqu’à une application en ligne, installable sur PC et Android, avec un APK téléchargeable. Les étapes 1 à 6 suffisent ; 7 et 8 sont facultatives.

GitHubgratuit · code, tests, APK
Vercelgratuit · site en ligne
Supabasegratuit · facultatif
Google Playpayant · facultatif

Remplacez toujours VOTRE_DEPOT par l’adresse de votre dépôt GitHub. Aucune action n’a été faite sur vos comptes : vous gardez la main sur chaque étape.

1

Préparer l’ordinateur

≈ 10 min

Deux logiciels gratuits suffisent : Node.js (pour construire et lancer l’application) et Git (pour envoyer le code sur GitHub).

  1. Installez Node.js 22 LTS depuis nodejs.org (bouton « LTS »), avec les options par défaut.
  2. Installez Git depuis git-scm.com, avec les options par défaut.
  3. Ouvrez un terminal : sous Windows, « Invite de commandes » ou « PowerShell » ; sous macOS, « Terminal ».
  4. Vérifiez l’installation avec les deux commandes ci-dessous : chacune doit afficher un numéro de version (Node.js : v22 ou plus).
node -v
git --version
2

Lancer l’application sur votre ordinateur

≈ 5 min

Avant de publier, vérifiez que tout fonctionne en local.

  1. Décompressez plan-maintenance-cms.zip (clic droit → Extraire tout).
  2. Dans le terminal, placez-vous dans le dossier décompressé avec cd. Astuce Windows : dans l’Explorateur, tapez cmd dans la barre d’adresse du dossier puis Entrée.
  3. Installez les dépendances puis lancez l’application (commandes ci-dessous). La première installation prend environ une minute.
  4. Ouvrez http://localhost:4173 dans votre navigateur. Allez dans l’onglet Tests : il doit afficher 19 / 19.
  5. Pour arrêter le serveur : Ctrl + C dans le terminal.
cd plan-maintenance-cms
npm install
npm start

Facultatif — lancer tous les tests automatiques : npx playwright install chromium puis npm test.

3

Publier le code sur GitHub

≈ 10 min

GitHub héberge le code, lance les tests et fabrique l’APK Android automatiquement.

  1. Créez un compte gratuit sur github.com.
  2. Cliquez sur + → New repository. Nom : plan-maintenance-cms. Public ou Private. Ne cochez rien (ni README, ni .gitignore, ni licence : le projet les contient déjà) → Create repository.
  3. Copiez l’adresse affichée par GitHub (elle finit par .git).
  4. Dans le terminal, dans le dossier du projet, lancez les commandes ci-dessous en remplaçant VOTRE_DEPOT par cette adresse.
  5. Au premier git push, une fenêtre de connexion GitHub s’ouvre : connectez-vous. (Si Git demande votre nom : git config --global user.name "Votre Nom" et git config --global user.email "vous@exemple.com".)
  6. Sur GitHub, ouvrez l’onglet Actions : deux traitements démarrent, CI (tests) et Android (APK). Ils doivent finir en vert ✓ (5 à 10 minutes).
git init
git add .
git commit -m "Initial production release"
git branch -M main
git remote add origin VOTRE_DEPOT
git push -u origin main

Sans terminal ? L’application GitHub Desktop (desktop.github.com) permet de faire la même chose avec des boutons : File → Add local repository → Publish repository.

4

Récupérer et installer l’APK Android

≈ 5 min

L’APK est fabriqué par GitHub à chaque envoi de code sur la branche main.

  1. GitHub → onglet Actions → Android (APK) → cliquez sur la dernière exécution (✓ verte).
  2. En bas de la page, section Artifacts : téléchargez plan-maintenance-cms-android (un fichier .zip).
  3. Décompressez-le : il contient plan-maintenance-cms-N-debug.apk.
  4. Copiez l’APK sur le téléphone (câble USB, Drive, e-mail…) et ouvrez-le.
  5. Android demande d’autoriser l’installation d’applications inconnues pour l’application utilisée (Fichiers, Chrome) : autorisez → Installer → Ouvrir.

L’APK « debug » sert aux tests et aux démonstrations. Pour Google Play, voir l’étape « Version signée ».

5

Mettre l’application en ligne avec Vercel

≈ 5 min

Vercel donne une adresse web publique (https) et redéploie automatiquement à chaque mise à jour.

  1. Allez sur vercel.com → Continue with GitHub.
  2. Add New… → Project → à côté de plan-maintenance-cms, cliquez sur Import.
  3. Ne changez aucun réglage : le fichier vercel.json indique déjà la commande de build (npm run build) et le dossier (dist).
  4. Cliquez sur Deploy. Après environ une minute, Vercel affiche l’adresse publique, par exemple https://plan-maintenance-cms.vercel.app.
  5. Vérifiez : le tableau de bord s’affiche, l’onglet Tests indique 19 / 19, et une adresse inventée (/abc) affiche la page 404.
  6. Désormais, chaque git push sur main met le site à jour automatiquement.

Domaine personnalisé : Vercel → votre projet → Settings → Domains, puis suivez les instructions DNS. Le HTTPS est automatique.

6

Installer l’application (PWA) sur PC et téléphone

≈ 2 min

Avec l’adresse Vercel, l’application s’installe comme une vraie application et fonctionne hors ligne.

  1. PC (Windows, macOS, Linux) : ouvrez l’adresse dans Chrome ou Edge → bouton Installer l’application dans l’en-tête vert (ou icône ⊕ de la barre d’adresse).
  2. Android : ouvrez l’adresse dans Chrome → menu ⋮ → Installer l’application. L’icône « Maintenance CMS » apparaît sur l’écran d’accueil.
  3. iPhone / iPad (sans App Store) : Safari → Partager → Sur l’écran d’accueil.
  4. Quand une nouvelle version est publiée, l’application affiche « Nouvelle version disponible » → Mettre à jour. Les données sont conservées.
7

Synchronisation entre appareils (Supabase) Facultatif

≈ 15 min

Facultatif. Sans cette étape, l’application fonctionne sans compte et les données restent sur chaque appareil. Avec elle : un compte e-mail et le même plan sur le PC et le téléphone.

  1. Créez un projet gratuit sur supabase.com (New project, choisissez une région proche, ex. Europe).
  2. SQL Editor → New query → collez tout le contenu du fichier supabase/migrations/20261110000000_plans.sql → Run.
  3. Project Settings → API : copiez Project URL et la clé publique anon / publishable. Jamais la clé service_role ni une clé sb_secret_… (le build les refuse).
  4. Authentication → URL Configuration : mettez votre adresse Vercel dans Site URL.
  5. Dans Vercel → projet → Settings → Environment Variables : ajoutez SUPABASE_URL et SUPABASE_ANON_KEY, puis Deployments → ⋯ → Redeploy.
  6. Dans GitHub → dépôt → Settings → Secrets and variables → Actions → onglet Variables : ajoutez les deux mêmes variables (pour que l’APK ait aussi la synchronisation).
  7. Vérifiez : application → Paramètres → section « Synchronisation » → Créer un compte.
8

Version signée et publication sur Google Play Facultatif

≈ 20 min

Facultatif. Nécessaire pour Google Play et pour des mises à jour d’APK sans désinstallation. Un compte développeur Google Play est payant (frais d’inscription unique).

  1. Créez une fois pour toutes une clé de signature avec la commande ci-dessous (keytool est fourni avec Android Studio ou tout JDK). Gardez le fichier et les mots de passe en lieu sûr : sans eux, plus aucune mise à jour possible sur Google Play.
  2. Convertissez la clé en texte : Linux / macOS base64 -w0 publication.jks (macOS : base64 -i publication.jks) ; Windows PowerShell : [Convert]::ToBase64String([IO.File]::ReadAllBytes("publication.jks")).
  3. GitHub → Settings → Secrets and variables → Actions → New repository secret : ANDROID_KEYSTORE_BASE64 (le texte), ANDROID_KEYSTORE_PASSWORD, ANDROID_KEY_ALIAS (planmaintenance), ANDROID_KEY_PASSWORD.
  4. Créez une version avec un tag (commandes ci-dessous) : GitHub crée une Release avec l’APK signé et le fichier .aab.
  5. Sur la Google Play Console : créez l’application, déposez le fichier .aab, complétez la fiche (captures dans docs/images/), la politique de confidentialité et le questionnaire, puis envoyez en test interne avant la production.
keytool -genkey -v -keystore publication.jks -keyalg RSA -keysize 2048 -validity 10000 -alias planmaintenance
git tag v2.0.0
git push origin v2.0.0
9

Publier une mise à jour

≈ 5 min

Le même geste met à jour le site, la PWA et l’APK.

  1. Modifiez le projet, puis vérifiez en local : npm start (et npm test si possible).
  2. Changez le numéro de version dans package.json et dans android/app/build.gradle (versionName), notez les changements dans CHANGELOG.md.
  3. Envoyez le code (commandes ci-dessous) : Vercel redéploie le site, les utilisateurs voient « Nouvelle version disponible », GitHub refabrique l’APK.
  4. Version Android officielle : créez un tag vX.Y.Z (voir l’étape précédente).
git add .
git commit -m "Version 2.1.0 : description des changements"
git push

Dépannage

ProblèmeSolution
« node » ou « git » n’est pas reconnuFermez et rouvrez le terminal après l’installation ; sinon réinstallez en gardant l’option « Add to PATH ».
git push refusé (authentication failed)Connectez-vous dans la fenêtre GitHub qui s’ouvre, ou utilisez GitHub Desktop. Les mots de passe GitHub ne sont plus acceptés dans le terminal.
Le traitement GitHub « Android (APK) » est rouge ✗Cliquez dessus pour lire l’étape en échec. Relancez avec Re-run jobs : un téléchargement réseau peut échouer ponctuellement.
Vercel : « Build refusé : … clé SECRÈTE »Vous avez collé la clé service_role. Remplacez-la par la clé anon / publishable.
« Application non installée » (APK)Le nouvel APK n’a pas la même signature que l’ancien. Exportez vos données (Paramètres → Exporter), désinstallez l’ancienne version, puis installez la nouvelle.
Le site affiche encore l’ancienne versionTouchez « Mettre à jour » quand le message apparaît, ou rechargez la page deux fois.

الموقع ما زال يُظهر النسخة القديمةاضغط « Mettre à jour » عند ظهور الرسالة، أو أعد تحميل الصفحة مرتين.
